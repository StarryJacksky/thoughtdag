# 研究工作台：共享文档缓冲、撤销和保存状态（T08）

记录日期：2026-10-05。本文是工程计划 T08 的交付说明：一个文件在应用里只有一份正在编辑的文本，所有视图共用它；它怎么保存、怎么撤销、文件在别处被改了怎么办、没保存的内容怎么不丢。

## 2. 它保证什么

- **一个文件一份文档。** 不管开了几个视图、怎么打开的、是不是同时打开的，都是同一份缓冲，文件只读一次。
- **每次编辑都说明它基于哪个缓冲版本。** 基于旧版本的编辑被拒绝，不做猜测性的合并。缓冲版本只增不减，撤销也是一个新版本。
- **“已保存”的意思是：缓冲里的内容就是文件里的内容，并且得到了确认。** 保存途中又输入的内容不算在这次保存里：保存完成后文档仍是“未保存”，随后再存一次。
- **保存不会盖掉别处的修改。** 那是冲突，由人来决定。
- **输入过的内容不丢。** 文档被放手之前，内容要么已经在文件里，要么在恢复稿里。

## 3. 接口

计划里的五个：`open(fileId, surfaceId)`、`applyEdit(documentId, edit)`、`save(documentId)`、`subscribe(documentId, listener)`、`closeView(surfaceId)`。

另外加了几个，原因如下：

| 接口 | 为什么要 |
| --- | --- |
| `undo` / `redo` | 撤销属于文档，不属于某个视图 |
| `setText(documentId, text, surfaceId)` | 给只知道整段文本的视图（普通文本框）用：服务算出差异，作为一次编辑 |
| `resolveConflict(documentId, 选择)` | 冲突由人解决，见第 6 节 |
| `status(documentId)` | 契约里的 `DocumentModel` 不含“为什么是这个状态”，这里给出：冲突的另一方、保存失败的原因、是否来自恢复稿、能否撤销 |
| `noteWorkspaceEvent(event)` | 工作区报告文件变化时，对应的文档跟上 |
| `keepDrafts()` | 窗口关闭时把所有未保存内容立刻写进恢复稿 |

监听者收到的变化里带着“改了哪里”（相对于修改前的文本），这样另一个视图可以把别人的输入应用到自己显示的内容上，而不是整段重画。

## 4. 保存

- 停止输入 1000 ms 后自动保存；再输入就重新计时。
- 一个文件同一时间只有一次保存在进行。保存途中再要求保存，排在它后面。
- 保存失败时内容保留，状态是“出错”，并写进恢复稿。之后自动再试 3 次，间隔 2、4、8 秒；仍然失败就停下，等人再点保存，或者等下一次输入。
- 不知道上一次有没有写成功时，用同一个操作 id 再问，宿主保证只做一次。内容变了才换新的 id。
- Windows 换行的文件，显示用 LF，写回时恢复 CRLF。BOM 由宿主保留。

## 5. 撤销

- 文档级：谁输入的，任何视图都能撤销。
- 连续输入（同一个视图、间隔不超过 700 ms、位置相连、没有换行）算一步。
- 撤销回到和文件一致的内容时，状态回到“已保存”，不会多存一次。
- 文件被别处改动而缓冲重新载入之后，撤销历史从那里重新开始：文件现在的内容不是一个可以撤销掉的步骤。

## 6. 文件在别处被改了

| 情形 | 结果 |
| --- | --- |
| 没有未保存内容 | 缓冲换成文件现在的内容，视图收到“重新载入” |
| 有未保存内容 | 立即进入冲突状态，不等到保存时才发现。自动保存停止 |
| 保存时才发现文件变了（没收到通知） | 同样进入冲突 |
| 自己的保存引起的通知 | 忽略：按操作 id 和内容哈希识别 |
| 文件不见了 | 状态是“出错：文件丢失”，缓冲保留并写进恢复稿；文件回来后继续，并补上保存 |

冲突时双方内容都在手边，三种解决办法：

- **用磁盘上的**：缓冲换成文件的内容。我的内容在撤销栈里，撤销一步就回来。
- **保留我的并覆盖**：以“人看到的那个版本”为前提保存。如果文件在此期间又变了，这是一次新的冲突，不会盲目覆盖。
- **两边都留在文本里**：把两份内容用标记分隔放进缓冲，由人手工整理。这种状态下不自动保存，等人明确保存。

## 7. 恢复稿

- 停止输入 250 ms 后，未保存的内容写进恢复稿；保存得到确认后，恢复稿清除。
- 恢复稿放在工作区自己的记录里，按文件身份存放，所以文件被移动、所在文件夹被改名之后仍然对得上。每个文件一份，整份替换。
- 打开文件时如果有恢复稿：
  - 它基于的版本就是文件现在的内容：恢复为“未保存的输入”，随后照常自动保存。撤销一步可以回到文件的内容。
  - 文件在此期间变了：进入冲突，不会用恢复稿覆盖。
  - 它和文件内容一样：丢弃。
- 关闭最后一个视图时，未保存内容先保存；存不了（冲突、只读、出错）就留在恢复稿里，下次打开还在。
- 恢复稿不是工作区里的文件：任何列表都不显示它，任何读取都够不到它，也不会作为模型输入。
- 只读的工作区不写恢复稿。

## 9. 没做的和已知限制

- **节点上的编辑器还是普通文本框。** CodeMirror 和不依附节点的文档表面是 T09、T10。
- **历史版本没有界面。** 宿主侧能列出和还原（见 M1 审查回应第 7 节），界面随 T10。
- **冲突没有逐行对比。** 现在只能三选一，或者把两份都放进文本手工整理。
- **撤销历史不跨关闭保存。** 文档被放手之后重新打开，撤销栈是空的（恢复稿恢复的那一步除外）。
- **通过门读到的文本不再报告是否带 BOM**（统一报告 `utf-8`）。保存时宿主照原样保留 BOM，所以内容不受影响，只是这个信息在页面一侧看不到了。
- **只在 macOS 上验证过。**
