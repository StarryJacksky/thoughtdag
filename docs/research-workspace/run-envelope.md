# 研究工作台：资源冻结与 Run Envelope（T11）

记录日期：2026-10-16。T11 是 M3 的第一个任务（计划第 7 节和第 12 节的 T11 条目）。之后的 T12（物化与权限）、T13（运行记录与重放）、T27（按 AI 目标冻结配置）都建立在它上面。

## 1. 做了什么

每次运行在发出之前，先把它读到的东西冻结下来，编成一份清单，也就是“运行信封”（`RunEnvelope`，契约在 T02 时已经定下）。具体分三步：

1. **冻结文件**：任务读到的工作区文件，有没保存的输入就先保存，再把当时的内容存成快照，交给运行的就是快照里的内容。之后文件怎么变，这次运行读到的都不变，事后也能把快照读回来。
2. **构建上下文**：仍然用唯一的上下文构建器 `buildContext`，只是画布上的文件副本先换成冻结后的内容。没有另起一套遍历规则。
3. **算两个摘要，发出前核对**：
   - `inputDigest`：模型被要求读的内容，包括按顺序排列的消息及其角色、每张图片的完整字节、每个输入的内容和所选的部分。发给哪个 AI 都不影响它；卡片的位置、是否折叠都不进入它。
   - `executionDigest`：在 `inputDigest` 之外，再加上目标及其版本、运行时和连接、模型和 effort、执行策略和工具、请求的形式（Agent 收到的是一段编好的提示，API 模型收到的是消息列表）。
   - 请求离开之前，再拿它和信封核对一次（`verifyDispatch`）。消息必须完全一致；模型必须一致；工具不能超出策略；图片要么原样，要么在模型看不见图片、且每张都有文字说明时整批去掉。途中多出一条系统消息或一个工具，都会被拦下。

运行不能按原样进行时就不发送，任务节点上写明原因，不记录任何回答版本。这样的情况有：文件丢了；编辑器里的内容和磁盘冲突；没保存的输入保存失败；选中的段落现在出现了不止一处，或者已经不在了；文件太大；画布上 PDF 一类的副本还不是文件现在的内容。

## 3. 接线

- 四个运行入口（提问、追问、原位重跑包括自动重跑、另开分支）在构建上下文之前调用 `freezeForRun`。这一步冻结文件，把画布上文本文件的副本换成冻结后的内容，冻结结果留给这次运行用。不能冻结时，任务直接标为“没有发送”。
- 运行函数在插入记忆和回忆之后、发送之前调用 `prepareRun`，传入实际要发的消息、图片和它们各自的来源。插入记忆、回忆或角色提示时，来源列表同步插入，保证消息和来源一一对应。
- 其他入口（扇出、合并、摘要节点等）没有事先冻结。对这些入口，`prepareRun` 只冻结上下文里确实出现的文件，并检查画布副本是否就是冻结内容；不是的话，把副本更新，这次不发送，再运行一次即可。如果来源和消息对不上（比如合并时给的来源是按节点而不是按消息排的），就不归属输入，摘要仍然覆盖实际消息。
- 发送那一刻，在 `onDispatch` 里调用 `verifyDispatch`；不一致就抛出 `DispatchRefused`，走“没有发送”的路径。
- 回答写入时一并记录 `lastRun`。

## 5. 没做的和限制

- **执行策略只是记录，还没有强制执行。** `policy` 写的是这次运行允许什么，真正的限制属于 T12。Agent 拿到的材料文件仍由 `materialsToDisk` 从画布副本写出；副本已经是冻结后的内容，但物化还没有按信封进行。研究模式的隔离也还没有实现。
- **PDF 只冻结整份文件。** 指定了页的 PDF 引用，模型读到的仍是整份 PDF 抽出的文字；只取所选页属于 T12。文本选区已经只把所选段落交给模型。
- **回忆条目没有单独列成输入。** 它们作为消息进入信封，所以在摘要里，但 `inputs` 里没有 `recall` 类的条目。
- **信封没有整体保存。** 回答上只记了 `lastRun` 这份精简记录。完整的运行记录、引用计数和快照清理属于 T13。
- **没有运行预览界面**（`RunPreview` 属于 T12）。
- **发送前的核对范围**：核对消息、图片、模型和工具；Agent 收到的那段编好的提示，以及运行时自己添加的系统提示，不在核对范围内。按计划 7.4 节，这一层不保证可审计。
- **画布副本的更新**：冻结时会把画布上文本文件的副本改成冻结后的内容，这和文件变化时副本的更新是一回事。PDF、图片和网页的副本如果还不是当前内容，这次运行会被拒绝，等副本更新后再运行。
