## 2. 新建文件的两个入口（T06）

**从文件树新建。** 文件落在选中的文件夹里（没选就是顶层），画布不动。点一个文件等于选中它所在的文件夹。

**从画布新建。** 调色板上的“新建文件”按钮，点击或拖到某处。文件落在工作区的 `Graph Files/` 里，画布上在指定位置出现一个指向它的节点。点击创建时，节点放在视野中央；那里已经有卡片就放到旁边，不叠在别的卡片上面。

两个入口共同遵守：

- 不新增任何连线。连线只能手动加。
- 不调用任何模型，不需要网络。
- 先建文件，再建节点。节点没建成时文件保留，提示里带一个“补上节点”的按钮，不会重复建文件。
- 每次创建一个独立的操作 id，重试不会建出两个文件。
- 类型菜单把上次选的类型排在最前面；也可以手输任意扩展名（字母数字，不带点）。
- 自动命名（`Untitled-001`、`Mindmap-001`）和模板内容由宿主侧决定，见 T04 的记录。
- 创建成功的提示里可以直接“在文件管理器中显示”，用来确认真实位置。

**画布还没有文件夹时。** 从画布新建会自动打开“这张画布自己的文件夹”：位置由桌面壳决定（用户数据目录下 `workspaces/<画布>`，也是它的 agent 运行的目录），不弹选择框。面板的“打开”菜单里也可以主动选它。

**画布记住自己的文件夹。** 画布元数据里只存 `workspaceId`，不存路径。桌面壳记着它被授权过的文件夹，重启后两边按 id 对上，不需要重新选。壳那边已经没有这个文件夹了，画布就回到“没有文件夹”的状态，它的文件节点显示为丢失。

## 3. 文件节点（T07）

文件节点是一个 `stepKind: 'file'` 的内容节点，多带一个 `resourceRef`。它持有文件内容的一份副本（就是节点的附件），沿连线进入上下文的是这份副本，所以现有的上下文组装不用改。

- **身份是 `fileId`。** 同一个文件可以有多个节点，它们共享同一个 `fileId`。
- **删节点不删文件。** 节点上的删除按钮只移除节点。
- **移动文件不移动节点。** 文件移到别处后，所有指向它的节点显示新位置，节点在画布上的位置不变。
- **移动失败不显示成功。** 节点上的路径只在工作区确认移动之后才更新。
- **外部修改会跟上。** 画布打开期间订阅它用到的每个工作区（自己的文件夹，加上节点所在的其他工作区）。文件被别的程序改了，节点的副本随之更新。
- **画布打开时对一次账。** 画布关着的时候文件可能被移动、修改、删除，打开时逐个文件对账。
- **丢失的文件显示重连卡片。** 状态是 `missing` 或 `ambiguous` 时，卡片说明它最后在哪里，并保留最后一份副本。点“去找它”会打开文件面板，在某个文件上点“就是它”完成重连。
- **刷新副本不进撤销历史。** 这是工作区在跟上文件，不是用户的操作。
- **旧的读取结果不会盖掉新的。** 同一个节点连续触发两次刷新时，只有最新的一次写入。
- **不是文本、或者超过 8 MiB 的文件只留引用。** 卡片会说明它的内容不会进入任何上下文。

缩到最小一档（图标档）时，文件节点和其他材料一样显示为图标。

## 4. 拖拽

应用内部的拖拽用一种专用类型，内容是结构化的 payload，只有三种：

| 种类 | 含义 |
| --- | --- |
| `file-ref` | 文件树里的一个文件（工作区 id、条目 id、名字） |
| `selection-ref` | 文档里的一段选区（一个 `ResourceRef`） |
| `graph-node` | 画布上的一个节点（节点 id） |

payload 里只有 id，没有路径。带多余字段（比如 `path`）、未知种类、引用格式不对的 payload 一律当作不存在。

- 树里的文件拖到画布：在落点建一个指向它的节点。
- 树里的文件拖到文件夹：移动文件。
- 节点上的路径标签拖到文件夹：移动节点指向的文件。
- 来自另一个工作区的文件或节点拖到文件夹：按复制导入。新文件有新的身份，标为副本，原文件不动。文件不会在工作区之间移动。

`selection-ref` 目前只有格式和落点处理，还没有产生它的界面，等文档编辑表面（M2）。

## 5. 从节点直接改文件

T06 的验收要求“两种入口都能打开可输入文档”，而共享文档缓冲是 T08 的事。所以这里先做了一个最小的版本，T08 会替换它：

- 点铅笔进入编辑，读到文本和它的版本。
- 保存时带着这个版本。文件在此期间被别的程序改过，保存不会落盘，卡片给出两个选择：载入磁盘上的版本，或者保留我的并覆盖。
- 打开着但没有改动时，文件在别处变了，直接换成新内容。
- 文件用的是 CRLF 换行时，显示用 LF，写回时恢复 CRLF。BOM 由宿主侧保留。
- PDF、图片、Word 等不是文本的文件没有编辑按钮。

## 6. ChatGPT 空间入口

“打开”菜单里和“打开文件夹”并列有一项“ChatGPT 空间”。点了之后如实说明目前打不开（没有可用的接口，见 T32 的报告），并提供“粘贴为副本”：把文本存成一个普通的本地文件，记下“复制自 ChatGPT 空间”和可选的具体位置。这个文件之后和其他本地文件完全一样，节点上带一个“副本”标记，不和原处保持同步。

## 8. 实现中发现并修掉的问题

1. **字节数组跨环境时认不出来。** 读字节的客户端用 `instanceof Uint8Array` 判断返回值，而字节是从另一个执行环境过来的，判断为假，节点因此拿不到内容副本。改为按“是不是字节视图”判断。
2. **测试里的画布加载撞进了后面的用例。** 上游的 `deleteNode` 会触发一次画布加载（`bootProjects`），第一次调用时它会从存储里重新读出画布。测试里它落在后一个用例中间，把那个用例的画布清空了。应用里启动时已经加载过，没有这个问题；测试改为先加载再开始。
3. **新卡片叠在旧卡片上。** 从画布新建的节点和从面板加入的节点都放在视野中央，后一个会盖住前一个，被盖住的卡片上的按钮点不到。这是桌面端测试里“去找它”按钮点不到时发现的。改为找旁边的空位。
4. **刷新副本污染撤销历史。** 最初用的是附件的增删动作，每次外部修改都会留下几步撤销记录。改为直接替换。
5. **BOM 差点写两次。** 宿主侧保存时已经保留 BOM，页面这边不能再加。

## 9. 和计划的出入

- `createDocument` 返回的是 `{ record, nodeId, nodeError? }`，不是计划里写的单个 `ResourceRecord`。因为“文件建成了但节点没建成”需要说得出来。
- `attachResource` 多一个参数：文件的记录。节点要显示名字和路径，调用方手里都有这份记录。
- `moveReferencedFile` 多一个可选参数：新名字。
- 类型表里没有 `template`。模板在宿主侧（`runtime/workspace/file-ops.cjs`），页面这边不持有文件内容的模板。

## 10. 没做的和已知限制

- **文件夹只能看，不能改。** 新建文件夹、文件夹的移动、改名、回收都没有界面。宿主侧有新建文件夹的能力，其余没有。
- **文件改名没有界面。** 宿主侧支持（移动时给新名字）。
- **别的程序新建的文件不会自动出现在树里。** 监听只管已登记的文件。需要点刷新。
- **从恢复区还原没有界面。** 回收之后引用它的节点显示为丢失。
- **面板打开时画布不让位。** 面板会挡住左侧的卡片，需要自己平移画布。右侧的焦点面板是会让位的。
- **空画布上没有调色板。** 上游的调色板只在画布有节点时显示，所以“从画布新建”在空画布上没有入口。文件面板始终可用。
- **换行混用的文件**从节点保存后会统一成 LF。
- **节点持有的是活引用的缓存，不是冻结的快照。** 冻结某个版本是 T11 的事。
- **导出的画布文件**会带上 `resourceRef`、相对路径提示和内容副本，不含绝对路径。在另一台机器上打开时，这些节点显示为丢失，副本仍可用。
- **只在 macOS 上验证过。**
