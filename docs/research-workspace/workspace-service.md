# 研究工作台：工作区授权与路径校验（T03）

记录日期：2026-10-03。本文是工程计划 T03 的交付说明：真实项目文件夹是怎么被打开的，一个文件操作在什么条件下被允许，以及谁可以发起这些调用。

T03 只做到“打开文件夹、列出内容、给文件登记身份”。新建、保存、移动和回收是 T04。

## 1. 文件

| 文件 | 内容 |
| --- | --- |
| `runtime/workspace/path-policy.cjs` | 路径校验：一个操作能不能落在某个路径上 |
| `runtime/workspace/registry.cjs` | 资源登记：哪个文件是哪个 `fileId` |
| `runtime/workspace/index.cjs` | 工作区服务：打开文件夹、列出、登记 |
| `runtime/workspace/ipc-guard.cjs` | 调用方校验 |
| `runtime/workspace/media-types.cjs` | 按扩展名给出媒体类型 |
| `src/lib/workspace/client.ts` | 界面一侧的客户端 |
| `desktop/main.js`、`desktop/preload.js` | 接线：`workspace:*` 通道和 `window.desktopWorkspace` |

## 2. 规则

**文件夹只能通过系统选择器加入。** 界面永远不传路径：打开之后，它用服务给的工作区 id 和条目 id 来指代文件夹和文件。条目 id 不是秘密，安全也不依赖它：每个传回来的 id 都重新过一遍路径校验。

**路径校验看的是解析后的真实位置，不是字符串。** 目标路径上每一段已存在的部分都会解析软链接，解析结果必须仍在工作区根目录之内。具体会被拒绝的：

- `..` 和 `.`，无论用哪种分隔符；
- 绝对路径、盘符、网络共享路径；
- 含 NUL 的路径；
- 通向工作区之外的软链接，读、列、新建都拒绝；
- 通过软链接做的任何修改，即使链接指向工作区之内；
- 工作区自己的记录目录 `.thoughtdag/`，不分大小写；
- 只读工作区里的任何修改；
- 新建时不可移植的名字：Windows 保留名、含 `< > : " | ? *` 或控制字符、以点或空格结尾。已经存在的这类文件在平台允许时仍然可以读。

**打开文件夹不读文件内容。** 打开和列出只读目录项，不读正文，不建索引。文件在第一次被使用时才登记身份，这时读的也只是元数据；登记记录里的内容哈希为空，直到 T04 真正读取内容。

**身份和路径分开。** `fileId` 给一次、之后不变；路径只是它上次被看到的位置。两个不同文件夹里的同名文件是两个资源。工作区自己的 id 存在文件夹里（`.thoughtdag/workspace.json`），所以同一个文件夹在另一台机器或另一个配置下打开，仍然是同一个工作区。

**登记文件只有一个写入者，整体替换。** 写临时文件、刷盘、改名。更新版本写的登记文件只读不重写；损坏的登记文件报错并保持原样，不会被覆盖。

**只读文件夹不写任何东西。** 不能写的文件夹以只读方式打开，不会在里面创建 `.thoughtdag`；本次会话里仍然给文件分配身份，但不保存。

**调用只接受应用自己的顶层页面。** `workspace:*` 的每次调用都检查来源：必须是应用窗口的顶层框架，并且显示的是应用自己的地址。页面里的子框架、别的窗口、被带到别处的应用窗口，一律拒绝。

**错误不带路径。** 拒绝时返回稳定的错误码和一句给人看的话，都不含绝对路径。

## 3. 验证

| 层 | 测试 | 说明 |
| --- | --- | --- |
| 路径校验 | `tests/host/path-policy.test.cjs` | 在临时目录里建真实的文件和软链接逐条验证 |
| 服务与调用方校验 | `tests/host/workspace-service.test.cjs` | 打开、列出、登记、只读、版本、损坏、关闭；调用方校验的各种来源 |
| 界面客户端 | `tests/unit/workspace-client.test.ts` | 主进程的回答不符合契约时拒绝；拒绝原因如何传到调用方 |
| 真实桌面应用 | `tests/e2e-desktop/workspace-door.spec.ts` | 启动 Electron，走预加载桥和 IPC |

真实桌面应用的测试用临时配置目录，并把会话存储指向空，所以不读真实的会话记录。它替换了一样东西：系统文件夹选择器，让它直接返回测试用的文件夹。运行方式：

```bash
npm run test:e2e:desktop
```

需要先 `npm run build`，并在 `desktop/` 下装过依赖。运行时屏幕上会短暂出现应用窗口。

在真实应用里确认的几件事：

- 选中的文件夹能打开、列出、登记，返回的数据里没有路径；
- 伪造的、想跳出工作区的条目 id 被主进程拒绝；
- 页面里的子框架拿不到桥接；
- 应用窗口被带到本机另一个端口上的页面之后，那个页面拿得到桥接，但每个 `workspace:*` 调用都被拒绝。

## 4. 顺带确认的一个既有问题

上面最后一条反过来说明了旧桥接的问题：应用窗口的导航规则允许顶层页面跳到本机任意端口，而旧的桥接（`agents:*`、`sessions:*`、`local:*` 等）不检查调用方。所以窗口一旦被带到本机别的页面，那个页面就能调用它们，包括发起 Agent 运行和往任意目录写材料文件。

这在真实应用里得到了确认，测试里保留为一条预期失败。它不是 T03 引入的，也不在 T03 的范围内，这里没有修。修法是给旧通道加上同样的调用方校验，并把导航限制在应用自己的地址内。

## 5. 这次没有做的

- 只在 macOS 上跑过。Windows 的保留名、盘符和网络共享路径是按规则拒绝的，但没有在 Windows 上实跑；Windows 上的软链接和大小写行为也没有验证。
- 路径校验和实际操作之间的时间差没有处理：别的程序在两者之间把目录换成链接，这里挡不住。T04 写文件时会用打开后的句柄再核对一次。
- 没有做界面：没有文件树，也没有“打开文件夹”的入口。那是 T06。
- 桌面打包脚本已经改成把契约目录一起带上，但没有实际打包验证过。
- 没有处理文件夹被移走或改名之后的重新关联，那是 T05。
